# Measurement and correctness scope

The primary measurement is a whole public encoder call on the same pageable packed host bytes, through complete compressed host output and stream synchronization. It includes H2D, color conversion/subsampling, DCT, entropy coding, compressed retrieval and formatting performed inside the call. GPUJPEG uses `perf_stats=false`. nvJPEG explicitly performs raw H2D, forced-GPU encode, compressed-host retrieval and synchronization inside the same kind of host wall-clock interval. File I/O, initial context/encoder construction and parameter setup precede the loop. Any first-call lazy work remains in the first sample, which is discarded with the other warmups. There is no persistent device-input advantage and no compressed-device-output shortcut.

Both GPUJPEG versions used the same public API harness compiled with NVCC optimization and linked to separate static libraries; original and candidate libraries used Release, SM86 and OpenGL disabled. The original is upstream revision 78e5eee3f75e0a2a2e6c1409000ac05d679b4af8. nvJPEG used its explicit GPU backend, baseline DCT, RI0 and standard Huffman tables. Hardware/software are recorded in `environment.json`. Default host input/output are pageable. Encoder creation, input preparation, optional gray derivation, output writes and quality calculations are outside warm timing.

Five rounds randomize both the eight-case order and the three encoder orders with seed 20261020, avoiding consecutive same-encoder runs at case boundaries. Each fresh process performs 110 calls and discards 10. Results contain 12,000 retained samples, 500 per encoder/image case, with 120 processes total. The primary table uses the median of five round medians and reports their minimum/maximum. All samples, the schedule and hashes remain available. The GPU had one owner, and no profiling or other CUDA jobs overlapped the benchmark. Original RI0 entropy runs on the CPU, so this host-dependent speedup applies to the recorded Xeon as well as the recorded GPU.

The encoder's requested restart interval is insufficient evidence of its output format. Every output passes an independent JPEG marker audit: no entropy RST markers, no nonzero DRI, complete EOI and no trailing bytes. The scanner distinguishes marker payloads and FF00 stuffing. All8 cases/all 5 rounds preserve exact original GPUJPEG JPEG bytes. That implies equal coefficients and public reconstruction. All eight nvJPEG component quantizers also match GPUJPEG, but its JPEGs and pixels differ. Source error is measured with one common CPU decoder, Pillow, using MSE and `10log10(255²/MSE)` PSNR over all byte channels. Both RGB vendors therefore use the same comparison decoder and chroma upsampling. Subsampled nvJPEG PSNR is 0.14–0.31dB higher on these inputs; matched quality numbers and quantizers do not make the encoders reconstruction-identical. The quality table retains those differences and compressed sizes.

The final correctness suite compares 86 fresh cases, 28 state-reuse outputs and 10 outputs from two concurrent encoders against the isolated original; one feature-disabled case separately verifies CPU fallback. The 78 small synthetic entropy audits are a subset, independently parsed to quantized coefficient hashes. They cover all 32 block-start bit offsets modulo32, all 256 FF input offsets modulo256, a terminal rawFF, legal padding lengths 0–7,4,534 actual16-bit Huffman symbols,919ZRL symbols, and |DCdifference| up to 2040. State changes cover tiny→4K scratch growth, gray/color, all sampling modes, separate component scans, qualities and RI0↔RI1/8/10. Two concurrent encoders use different dimensions, quality and sampling on separate streams, initialized sequentially and device-synchronized before host threads start.

The recorded frozen candidate has executable SHA256 f11692097089eaba117fb7ee531eea5c954418461bc4233c746b71e3f7149692, library 1e440031b21c010450b55b00b2704bd077113b7352a34c92bf7fa680758dfea8 and helper source 20499e59f88855db876d948b66e16602306bc7dfbd2654bc32b21dcc30ff29e4. The benchmark validates source/library/executable/nvJPEG DLL and input hashes before/after. A later formatting-only removal of one final newline from the helper and documentation is separately recorded by EOF byte comparison and GPU instruction comparison; the measured binary provenance remains explicit.

Whole-encoder memcheck and synccheck each report zero errors on the final candidate. The original whole-encoder racecheck reports 72 warnings in the existing DCT kernel; the first candidate control shows the same unchanged DCT warnings. The final focused racecheck excludes only that DCT kernel and checks all new RI0 kernels plus CUB, reporting zero hazards/errors/warnings. This supports the new stages; it does not claim the entire upstream encoder is racecheck-clean. Sanitizer timings are excluded from performance results.

The natural Q90 candidate speedup is 7.71–13.04× over original GPUJPEG. Its measured latency is 2.3–12.7% higher than nvJPEG. These are transfer-inclusive values on this machine, with the output-quality qualifications above. A separate24-process small-image diagnostic shows tiny gray 1×1 and32×32 regress by 2.41× and 2.89×;127×65 noise420 improves 1.12× and512×512 noise420 improves 10.18×. The new path remains enabled for these eligible tiny images; no CPU size threshold was introduced or hidden in the matrix.
